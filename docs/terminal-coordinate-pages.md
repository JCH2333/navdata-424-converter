# 终端航路点坐标页

终端目录中由 `Charts.csv` 索引的“航路点坐标”PDF 是终端航路点的证据来源。解析器优先按 PDF 中标识符和坐标的实际渲染位置配对，以抵抗文字对象流顺序错乱；无法形成位置配对时，才要求标识符列与坐标列数量完全一致后配对。

每个已接受点保留机场、标识符、PDF 相对路径、页码和 PDF SHA-256。它们与 `DESIGNATED_POINT.csv` 保持分离。进入 Fenix 候选前，必须有同机场数据库编码页的明确航段引用；坐标页中的目录、跑道或装饰性文字不会直接写入 `Waypoints`。写入前仍须完成物理位置去重、来源优先级、确定性 ID 阶段和与本地成品的只读对照。

无法配对的坐标页会作为 `terminal-coordinate-page` 拒绝记录写入转换报告，不能静默忽略。2608 当前已知的异常页为 `ZHXY`、`ZLZY`、`ZPDQ` 和 `ZPNL`。

使用 `inspect-terminal-waypoint-coverage` 可对照官方模板和本地成品。匹配条件是标识符相同且坐标距离小于 0.02 海里；对未匹配点，报告还会区分成品是否存在同址但不同标识符的点。报告会把样本列出，供后续排查，不会把成品数据作为转换输入。

当前候选生成会按终端坐标页、`DESIGNATED_POINT.csv`、新增台站同址点三个独立阶段写入航点。它只使用官方库和原始数据，仍需以本地成品验证终端筛选、ID 阶段和物理行顺序；终端程序尚未完成前，所有这类候选均不可部署。

“数据库编码”页按 PDF 原生文字对象的渲染位置排序后提取。航段类型与固定点标识有时是相邻的 PDF 文本行，旋转的图面警告文字也可能残留在表格行前；解析器只在同一行提取标准航段字段，并将其配对为可追溯的程序固定点证据。该集合用于验证终端点是否被程序引用，但不会单独作为丢弃其他坐标页点的依据。

除带有 SID/STAR 名称的标题外，数据库编码页还会以“跑道进近过渡”“跑道进近”“跑道复飞”直接分段。解析器将这些原文段分别归入 `R{跑道}`，并保留过渡固定点标识；标题明确标有 `-W/-X/-Y/-Z` 时，后缀会保留在同一进近业务键中，复飞段也使用相同后缀。它们是后续建立 IAP 计划的输入；在计划与所有段的顺序、引用完整性尚未验证前，不会写入 `Terminals`。

加载中间模型时，每份数据库编码图还会按连续的程序名、类型、跑道和过渡固定点聚合为有序 `ProcedureSegment`。每段保留原始图页来源和每条 `ChartTerminalLeg`；跨页或跨标题的段不自动拼接，避免从版面顺序推断不存在的连线。

对 SID/STAR，程序写入器目前只接受 `CA`、`CF`、`DF`、`IF` 和 `TF` 航段，且每个有固定点的航段必须在同机场坐标页和目标 `Waypoints` 中唯一匹配。满足条件时会同时写入 `Terminals`、`TerminalLegsEx` 和 `TerminalLegs`；扩展行必须先于主航段行写入，因为 Fenix schema 的主航段外键引用扩展行。未唯一匹配的固定点、`RF`、`HM` 等未建立字段规则的航段会进入转换报告，绝不以直线段替代。

使用 `inspect-procedure-plan-coverage` 可将这些计划映射到 Fenix 的业务键后与本地成品差分做只读核对。无后缀的 `R{跑道}` 只表示数据库页明确给出的基准进近；不得把它自动复制为 X/Y/Z 变体，只有标题本身给出后缀时才能保留该变体。

Fenix 程序名保留图表后缀：三位数字的 `Pxxx` 去除首位数字，超过三位的名称截为前三位。例如 `P389-09D` 为 `P8909D`，`P528-9ZD` 为 `P289ZD`，`KAKAT-9ZA` 为 `KAK9ZA`。名称映射必须继续与跑道和航段序列交叉验证后才能写入程序表。

Fenix 的 `Terminals.Proc` 中，`1` 为进场、`2` 为离场、`3` 为进近。数据库页标题中的“进场/离场”优先于程序名后缀判定类型。

加载 NAIP 时会保留每个“数据库编码”页的图表、页码、哈希、程序标签、跑道和航段固定点证据。候选报告会列出这些证据数量；它们在程序映射完成前不会被直接写入 Fenix `Terminals` 表。

`DESIGNATED_POINT.csv` 的空 FIR 记录会按坐标归类；已确认的边界点使用显式国家码映射。指定点与官方库同标识符、近距离且国家码相同的记录会保留官方行；不同标识符的同址点不会被此规则删除。
