# 终端航路点坐标页

终端目录中由 `Charts.csv` 索引的“航路点坐标”PDF 是终端航路点的证据来源。解析器优先按 PDF 中标识符和坐标的实际渲染位置配对，以抵抗文字对象流顺序错乱；无法形成位置配对时，才要求标识符列与坐标列数量完全一致后配对。

每个已接受点保留机场、标识符、PDF 相对路径、页码和 PDF SHA-256。它们与 `DESIGNATED_POINT.csv` 保持分离，尚未直接写入 Fenix `Waypoints`；写入前必须完成物理位置去重、来源优先级、确定性 ID 阶段和与本地成品的只读对照。

无法配对的坐标页会作为 `terminal-coordinate-page` 拒绝记录写入转换报告，不能静默忽略。2608 当前已知的异常页为 `ZHXY`、`ZLZY`、`ZPDQ` 和 `ZPNL`。

使用 `inspect-terminal-waypoint-coverage` 可对照官方模板和本地成品。匹配条件是标识符相同且坐标距离小于 0.02 海里；对未匹配点，报告还会区分成品是否存在同址但不同标识符的点。报告会把样本列出，供后续排查，不会把成品数据作为转换输入。

当前候选生成会按终端坐标页、`DESIGNATED_POINT.csv`、新增台站同址点三个独立阶段写入航点。它只使用官方库和原始数据，仍需以本地成品验证终端筛选、ID 阶段和物理行顺序；终端程序尚未完成前，所有这类候选均不可部署。

“数据库编码”页单独采用快速文本提取。航段类型与固定点标识有时是相邻的 PDF 文本行，解析器会将其配对为可追溯的程序固定点证据。该集合用于验证终端点是否被程序引用，但不会单独作为丢弃其他坐标页点的依据。

`DESIGNATED_POINT.csv` 的空 FIR 记录会按坐标归类；已确认的边界点使用显式国家码映射。指定点与官方库同标识符、近距离且国家码相同的记录会保留官方行；不同标识符的同址点不会被此规则删除。
